## Практические работы

### 2. Конкурентный контейнер

Для выполнения работы следует:

- завести разделяемый том в Docker, который можно подключать к нескольким контейнерам;
- подготовить `Dockerfile` и скрипт на POSIX Shell, с помощью которых можно создать образ контейнера для конкурентного управления файлами.

Под конкурентным управлением файлами мы подразумеваем следующие действия:

1. Выполняются поочерёдно (бесконечно в цикле) две операции, между которыми всегда есть задержка в одну секунду: создание файла в каталоге общего тома и его последующее удаление.
2. Для определения имени файла следует выбрать первое незанятое имя из последовательности `001`, `002`, `003` и т. д.
3. В файл нужно записать случайно сгенерированный идентификатор контейнера (контейнер записывает во все свои файлы один и тот же идентификатор) и порядковый номер созданного файла для этого контейнера (в первый записывается `1`, во второй `2` и т. д.).
4. Определение незанятого имени и создание файла с ним должно проводиться как атомарная операция (т. е. этот фрагмент должен быть внутри блока с вызовом `flock` на служебном файле синхронизации). Атомарная операция должна длиться как можно меньше.

Контейнер будет проверяться с запуском в единственном экземпляре, с запуском десяти экземпляров и с запуском 50 экземпляров. Во всех случаях работа должна быть стабильной и исключать race condition.
